# /team-ecosystem-ca-agent

**Purpose:** Activate the optional, default-installed `agentic-team-ecosystem` skill to run a step-by-step, multi-team Agentic AI workflow across Groups 1–4 and Teams 1–14.

## When to run

**MUST** invoke when the Developer wants full multi-team orchestration (or a specific step/domain track) using the `agentic-team-ecosystem` playbook.

## Inputs

- **MUST** read `AGENTS.md`, `.agents/skills/agentic-team-ecosystem/SKILL.md`, and the relevant `references/*.md` file for the active step only.
- **MUST** classify the project domain (`SaaS`, `E-commerce`, `Brand`, `Software`, `App`, `ML/DL/Data Science`, `Computer Vision`, `OS`) before activating Group Main Agents.

## Procedure

1. **MUST** execute **Step 0 (Intake & Domain Classification)** with **only Main Agent + Team 14 (Manual Workflow Guider)** active—never trigger Teams 1–13 at once.
2. **MUST** proceed strictly **step-by-step (Steps 0–9)** using **Just-In-Time (JIT) Opt-In Activation**: before activating any team, either wait for the Developer's explicit request or emit a **Team Activation Notice** (`01-hierarchy-and-auto-triggers.md`) and wait for Developer confirmation.
3. **MUST** notify and ask to trigger **Team 1** Kanban & Google Sheet CSV export (`Project-Manager-Dashboard` `/api/kanban-export`) immediately after **Step 3 (Frontend / Interface Sensory Demo)** is approved.
4. **MUST** obey SDD-Vibe spec-lock, Red-Green-Refactor TDD, `logs/*.log` hygiene, and security-first vetting before installing any external skill/MCP/plugin.

## Stop conditions

**MUST** stop and ask the Developer on domain ambiguity, missing gate approval, security/secret leak findings, or unauthorized edits to `APPROVED` specs.
